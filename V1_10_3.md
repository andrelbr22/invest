# Investment Engine V1.10.3

## Auditoria realizada

- os pedidos manuais chegaram ao workflow do GitHub;
- as execuções `#3` e `#4`, solicitadas em 23/08/2026 às 17h16 e 17h27, falharam antes de iniciar qualquer backtest;
- a falha ocorreu durante a preparação do banco: o Secret `DATABASE_ADMIN_URL` continha um endereço `https://`, que foi interpretado incorretamente como um dialeto do SQLAlchemy;
- o repositório possui `DATABASE_ADMIN_URL`, mas não possui o Secret alternativo `DATABASE_URL`;
- como o workflow parava antes de criar o lote, o painel não tinha registro para exibir.

## Correções

- o site registra cada pedido no PostgreSQL privado antes de solicitar sua execução ao GitHub;
- o identificador do pedido acompanha o workflow e permite correlacionar os dois históricos;
- o painel exibe os estados Na fila, Executando, Concluído e Falhou;
- falhas do GitHub são refletidas no registro do banco quando o administrador abre o painel;
- o workflow possui uma validação inicial da conexão e encerra com instrução clara, sem revelar a senha;
- se uma das duas URLs estiver inválida, o motor usa a outra quando ela for uma conexão PostgreSQL válida;
- o pedido não é recriado pelo GitHub, evitando duplicidade;
- não há migração de banco.

## Instrução histórica desativada

Não configure `DATABASE_ADMIN_URL` no GitHub. Desde a V1.12.0, o workflow usa
PostgreSQL temporário e devolve os resultados pela rota HTTPS autenticada.
Consulte `CORRIGIR_SECRET_GITHUB_V1103.md`.
